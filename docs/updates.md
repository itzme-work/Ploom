# Обновление Ploom

Пользователь устанавливает первый подписанный пакет из Releases официального itzme-work/Ploom. Для следующей версии в настройках нажимает **Проверить обновления → Обновить Ploom** и подтверждает системную установку. При активной автопроверке доступная версия появляется после запуска. На Android при первой установке из Ploom система может запросить разрешение для этого источника. Сборки из Google Play направляют в магазин.

Windows скачивает Ploom.exe из тега выбранной версии, проверяет подпись Tauri, включая подписанный номер версии, и передаёт управление интерактивному NSIS. Эта подпись проверяется самим клиентом. Windows может отдельно показать SmartScreen для EXE без Authenticode. Android проверяет подписанное содержимое APK, совпадение сертификата и package name, а также возрастающий versionCode. Обе платформы обновляют приложение на месте. Если ОС сообщает о несовместимой подписи, остановите установку, сохранив существующие данные. Тестовые debug APK обычно подписаны другим ключом.

Для настройки и выпуска из одного браузера используйте [мастер GitHub Codespaces](browser-release.md). Ниже — альтернатива с локальной генерацией.

## Владелец — один раз

1. Перенесите проверенные изменения в основную ветку официального репозитория. GitHub регистрирует ручной workflow из ветки по умолчанию.
2. На личном Windows x64 ПК с защищённым диском установите GitHub CLI, выполните gh auth login, распакуйте исходники основной ветки и запустите из PowerShell `.\scripts\windows\SetupRelease.ps1`. Мастер создаёт отдельные постоянные ключи в %LOCALAPPDATA%\PloomRelease\keys. Сделайте зашифрованную резервную копию каталога и сохраните пароли в менеджере. Мастер регистрирует публичные идентификаторы и недостающие секреты в Environment **ploom-release**, передавая закрытые значения через stdin. Повторный запуск сверяет публичные привязки и пропускает существующие секреты. При наличии более ранних публичных выпусков используйте исходные ключи этих выпусков. Их замена требует отдельной миграции.
3. В GitHub Settings → Environments → ploom-release ограничьте deployment branches основной веткой. Доступ к основной ветке и workflow подписи должны иметь только доверенные сопровождающие. При необходимости добавьте required reviewers.

## Каждая новая версия

По умолчанию **Build only** готовит проверенные артефакты без создания релиза. Для публикации откройте **Actions → Publish Ploom → Run workflow**. Оставьте основную ветку, введите новую версию (например 0.1.1 или 0.1.1-beta.1), выберите Publish и подтвердите публикацию флажком и нажмите **Run workflow**. Если включены required reviewers, утвердите deployment. Матрица собирает Windows x64 и Android ARM64, подписывает пакеты, проверяет подписи и совместимость, формирует latest.json внутри тега и публикует GitHub Release после загрузки всех файлов. Используйте новый номер версии для каждой публикации. При сбое загрузки проверьте черновик в Releases перед повтором.

Для обычных тестовых сборок достаточно GitHub Actions → Foundation → Artifacts. Репетиция с Tailscale, отдельным HTTPS-стендом и приватной копией остаётся дополнительным способом проверить переход до публикации. ### Первая подписанная сборка 0.3.0

После ревью изменений и слияния с основной веткой владелец выбирает **Actions → Publish Ploom → Run workflow → 0.3.0 → Build only**. Подтверждение публикации оставьте выключенным. Используются существующие секреты окружения ploom-release. Получив зелёный результат, проверьте оба задания signed-connection. Появление артефакта verified-release означает успешную проверку подписей; проверка установленного приложения выполняется следующим заданием.

На Windows проверяются установка NSIS поверх 0.2.0, библиотека и настройки WebView2, отсутствие Wintun в установленном дереве и сетевой ответ через Local Proxy и System Proxy. На Android используется подписанный ARM64 APK, эмулятор API 30 с поддержкой ARM64, системное согласие VPN и контрольный сервер. Тест сохраняет профиль на 0.2.0 и использует тот же профиль после обновления через adb install -r. Это проверяет замену пакета и прохождение трафика, не проверяя доставку через GitHub Releases.

Оригинальные пакеты 0.2.0 берутся из verified-release запуска 45560158367. GitHub указывает срок хранения до 28 ноября 2026, 06:32 UTC. После истечения срока потребуется сохранённая точная копия этого артефакта в доверенном запуске официального репозитория; для такого запуска предусмотрена Actions variable PLOOM_020_BASELINE_RUN. Проверка закреплённых SHA-256 действует для обоих источников.

В комплекте 0.3.0 Ploom-source.tar.gz содержит исходники Ploom и закреплённого sing-box, патчи и сценарии сборки, Go vendor, Rust vendor и пакеты frontend по lockfile. Для Windows дополнительно прилагается windows-core-buildinfo.txt. DLL Wintun исключена из установщика и из каталога Go vendor в поставляемом архиве. Windows TUN остаётся задачей 0.3.1.
