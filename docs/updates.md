# Обновление Ploom

Пользователь устанавливает первый подписанный пакет из Releases официального itzme-work/Ploom. Для следующей версии в настройках нажимает **Проверить обновления → Обновить Ploom** и подтверждает системную установку. При активной автопроверке доступная версия появляется после запуска. На Android при первой установке из Ploom система может запросить разрешение для этого источника. Сборки из Google Play направляют в магазин.

Windows скачивает Ploom.exe из тега выбранной версии, проверяет подпись Tauri, включая подписанный номер версии, и передаёт управление интерактивному NSIS. Эта подпись проверяется самим клиентом. Windows может отдельно показать SmartScreen для EXE без Authenticode. Android проверяет подписанное содержимое APK, совпадение сертификата и package name, а также возрастающий versionCode. Обе платформы обновляют приложение на месте. Если ОС сообщает о несовместимой подписи, остановите установку, сохранив существующие данные. Тестовые debug APK обычно подписаны другим ключом.

## Владелец — один раз

1. Перенесите проверенные изменения в основную ветку официального репозитория. GitHub регистрирует ручной workflow из ветки по умолчанию.
2. На личном Windows x64 ПК с защищённым диском установите GitHub CLI, выполните gh auth login, распакуйте исходники основной ветки и запустите из PowerShell `.\scripts\windows\SetupRelease.ps1`. Мастер создаёт отдельные постоянные ключи в %LOCALAPPDATA%\PloomRelease\keys. Сделайте зашифрованную резервную копию каталога и сохраните пароли в менеджере. Мастер регистрирует публичные идентификаторы и недостающие секреты в Environment **ploom-release**, передавая закрытые значения через stdin. Повторный запуск сверяет публичные привязки и пропускает существующие секреты. При наличии более ранних публичных выпусков используйте исходные ключи этих выпусков. Их замена требует отдельной миграции.
3. В GitHub Settings → Environments → ploom-release ограничьте deployment branches основной веткой. Доступ к основной ветке и workflow подписи должны иметь только доверенные сопровождающие. При необходимости добавьте required reviewers.

## Каждая новая версия

**Actions → Publish Ploom → Run workflow**. Оставьте основную ветку, введите новую версию (например 0.1.1 или 0.1.1-beta.1), подтвердите публикацию флажком и нажмите **Run workflow**. Если включены required reviewers, утвердите deployment. Матрица собирает Windows x64 и Android ARM64, подписывает пакеты, проверяет подписи и совместимость, формирует latest.json внутри тега и публикует GitHub Release после загрузки всех файлов. Используйте новый номер версии для каждой публикации. При сбое загрузки проверьте черновик в Releases перед повтором.

Для обычных тестовых сборок достаточно GitHub Actions → Foundation → Artifacts. Репетиция с Tailscale, отдельным HTTPS-стендом и приватной копией остаётся дополнительным способом проверить переход до публикации.
