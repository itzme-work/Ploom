# Совместимость Android в Ploom 0.3.0

Целевая нижняя граница поддержки — Android 9 (API 28). Для интерфейса нужен актуальный для устройства Android System WebView. Из манифеста ARM64 debug APK коммита 7cb874a фактически считаны идентификатор work.itzme.ploom, версия 0.3.0, minSdk 24 и targetSdk 37. Нижний предел установки сохранён для совместимости с существующими установками. Работа на API 24–27 не прошла приёмку. Нативная библиотека собирается с Android API 24, как в стандартном варианте сборки sing-box 1.14.4. CI проверяет итоговый манифест обоих APK. На каждой версии запускается один и тот же сценарий передачи трафика через установленный клиент. Шесть конфигураций в workflow означают покрытие планом испытаний. Фактические результаты привязаны к коммиту в Actions. Отсутствие сотового транспорта на эмуляторе допускает проверку восстановления Wi-Fi после потери сети. Для подтверждения Wi-Fi ↔ мобильный интернет нужен доступный второй транспорт. [Каталог образов Google](https://dl.google.com/android/repository/sys-img/google_apis/sys-img2-3.xml)

**Архитектуры.** ARM64 — целевой APK для телефонов и планшетов с 64-битной Android. CI проверяет выравнивание ELF для страниц 16 КиБ. x86_64 — отдельный APK для эмуляторов. Для 32-битной системы ARMv7 устанавливаемого пакета пока нет. Поддержку ARMv7 потребуется подтвердить отдельными сборками Rust, libbox и испытаниями памяти на 32-битной ОС.

**Разрешения.** VpnService запрашивает согласие при подключении. Начиная с API 31 клиент использует выбор лучшей физической сети системой. На старых версиях применяется NetworkCallback. Камера запрашивается при открытии сканера. Для обновления APK требуется системное подтверждение. Результаты теста VPN не подтверждают работу камеры, доставки уведомлений и обновлений на каждой версии. Эти сценарии, повороты планшета и ограничения энергосбережения производителей требуют отдельных проверок.

На API 33 и новее разрешение уведомлений запрашивается кнопкой активной VPN-сессии. На API 37 при targetSdk 37 доступ к локальной сети требует отдельного системного согласия. Ploom запрашивает его для локального адреса после подтверждения адреса и порта в приложении. Публичный сервер этого запроса не вызывает. [Правила локальной сети Android](https://developer.android.com/privacy-and-security/local-network-permission)

### Android 7 и 8

API 24–27 удовлетворяют нижней границе APK и нативной библиотеки. На API 24–27 установщик требует криптографически проверенную для данной ОС подпись APK Signature Scheme v2. Сертификаты подписантов, полученные apksig, должны точно совпасть с полным набором GET_SIGNATURES установленного приложения и архива. На API 28+ используется SigningInfo. Ротация с изменением текущего набора подписантов отклоняется. Для официальной поддержки нужны отдельные испытания холодного запуска, совместимого WebView, аппаратного хранилища ключей, foreground-службы и обновления поверх предыдущей версии. Для старых ОС следует испытать строгую проверку того же подписанта на паре APK с проверкой подписи v2, включая отрицательные тесты. Доступность обновлений безопасности ОС и WebView зависит от модели устройства. Официальная нижняя граница поддержки остаётся Android 9.

**Исследование ARMv7.** Пакет Go experimental/libbox версии 1.14.4 успешно скомпилирован для GOOS=android, GOARCH=arm, GOARM=7 с теми же тегами протоколов и CGO_ENABLED=0. Это проверка исходников Go. В [прогоне 8ea2e11](https://github.com/itzme-work/Ploom/actions/runs/45739101820/job/139644029861) успешно собран настоящий ARMv7 APK с minSdk 24, обе библиотеки прошли проверку ELF32 ARM. Отдельное задание armv7-evaluation собирает настоящий JNI AAR и Tauri APK с NDK, проверяет minSdk и заголовки ELF32 ARM обеих библиотек. Испытание установленного APK, расход памяти и поведение на физическом 32-битном устройстве остаются открытыми.
