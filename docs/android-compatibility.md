# Совместимость Android в Ploom 0.3.0

Целевая нижняя граница поддержки — Android 9 (API 28). Для интерфейса нужен актуальный для устройства Android System WebView. Из манифеста ARM64 debug APK коммита 7cb874a фактически считаны идентификатор work.itzme.ploom, версия 0.3.0, minSdk 24 и targetSdk 37. Нижний предел установки сохранён для совместимости с существующими установками. Работа на API 24–27 не прошла приёмку. Нативная библиотека собирается с Android API 24, как в стандартном варианте сборки sing-box 1.14.4. CI проверяет итоговый манифест обоих APK. [Проверенный комплект](https://github.com/itzme-work/Ploom/actions/runs/45630497588/artifacts/15031995885)

| Android | API | Что проверяет матрица |
|---|---:|---|
| 9 | 28 | Запуск WebView, системное согласие VPN, монитор сети до API 31 |
| 11 | 30 | Жизненный цикл foreground-службы и системное согласие |
| 13 | 33 | Работа VPN при стандартных настройках разрешений уведомлений |
| 15 | 35 | Смена доступной сети, отключение, повторное подключение |
| 16 | 36 | Совместимость установленного клиента с новыми ограничениями ОС |
| 17 | 37 | Стабильный образ Google APIs x86_64 android-37.0 |

На каждой версии запускается один и тот же сценарий передачи трафика через установленный клиент. Шесть конфигураций в workflow означают покрытие планом испытаний. Фактические результаты привязаны к коммиту в Actions. Отсутствие сотового транспорта на эмуляторе допускает проверку восстановления Wi-Fi после потери сети. Для подтверждения Wi-Fi ↔ мобильный интернет нужен доступный второй транспорт. [Каталог образов Google](https://dl.google.com/android/repository/sys-img/google_apis/sys-img2-3.xml)

**Архитектуры.** ARM64 — целевой APK для телефонов и планшетов с 64-битной Android. CI проверяет выравнивание ELF для страниц 16 КиБ. x86_64 — отдельный APK для эмуляторов. Для 32-битной системы ARMv7 устанавливаемого пакета пока нет. Поддержку ARMv7 потребуется подтвердить отдельными сборками Rust, libbox и испытаниями памяти на 32-битной ОС.

**Разрешения.** VpnService запрашивает согласие при подключении. Начиная с API 31 клиент использует выбор лучшей физической сети системой. На старых версиях применяется NetworkCallback. Камера запрашивается при открытии сканера. Для обновления APK требуется системное подтверждение. Результаты теста VPN не подтверждают работу камеры, доставки уведомлений и обновлений на каждой версии. Эти сценарии, повороты планшета и ограничения энергосбережения производителей требуют отдельных проверок.
