## Условия распространения

sing-box распространяется по GPL-3.0-or-later. Upstream также запрещает производным работам использовать имя или подразумевать связь с приложением без разрешения. При прямом связывании через libbox план выпуска должен предусматривать GPL-совместимое распространение комбинированной программы, доступ к полному соответствующему исходному коду точной поставки, скриптам сборки, изменениям и применимым сведениям для установки. Уведомления Apache-2.0 и авторство исходных файлов Ploom сохраняются. Владелец согласовал условия комбинированной поставки. До распространения нужны инвентаризация транзитивных лицензий и проверка комплекта исходников. Самостоятельный запуск инструментов в стенде не меняет лицензию репозитория. [Лицензия выбранной версии](https://github.com/SagerNet/sing-box/blob/c005f35300ce76427dc285481ec5695f5b179cd2/LICENSE)

## Испытание передачи TCP

На Linux x64 все три движка последовательно передали один и тот же массив случайных данных объёмом 4 МиБ. Клиент стенда открывает SOCKS5 на loopback, движок связывается с фиксированным HTTP CONNECT-сервером, тот передаёт запрос единственному разрешённому локальному серверу. Проверяются все байты ответа и число обращений к посреднику. Загрузки сверяются с закреплёнными SHA-256 до запуска. Команда для CI — bash scripts/engine-lab/run.sh.

| Движок | Старт до запроса, мс | Приём, МиБ/с | Пиковая RSS, КиБ | CPU, с | Файл Linux, байт |
|---|---:|---:|---:|---:|---:|
| sing-box | 62,5 | 186,0 | 55316 | 0,07 | 81416421 |
| Xray | 17,7 | 380,7 | 30512 | 0,02 | 35434620 |
| Mihomo | 27,5 | 386,6 | 42140 | 0,03 | 61948030 |

Медианы трёх последовательных успешных прогонов по каждому столбцу. Малый объём и локальная сеть дают большой разброс. В предварительном прогоне Mihomo один раз закрыл поток до получения данных. Размер файла Linux не определяет размер будущего APK или NSIS.

| Режим или протокол | Подтверждение в Ploom |
|---|---|
| HTTP CONNECT outbound через локальный SOCKS5 inbound | Частично. Реальная передача только на Linux в стенде |
| SOCKS5 outbound, HTTPS proxy, VLESS/REALITY/Vision, VMess, Trojan, Shadowsocks, Hysteria2, TUIC, WireGuard | Требуют проверки исходящего соединения для каждой комбинации |
| Android VpnService, Windows TUN и System Proxy | Не реализованы в этой ветке |
| IPv6, UDP, DNS через туннель, восстановление маршрутов, Kill Switch | Требуют отдельных системных испытаний |

Статус в интерфейсе остаётся отключённым. Следующие этапы требуют передачи TUN-дескриптора и защиты сокетов Android, управления привилегиями Windows, привязки статистики к активной сессии и испытаний восстановления после сбоя. Редактор политик остаётся задачей 0.4.0.
