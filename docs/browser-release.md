# Выпуск через браузер GitHub

## Если новый Codespace открылся в Recovery Mode с ошибкой 1302

Если вы уже скачали `partial.age`, сохраните архив, его пароль и старый Codespace. Следующие действия выполняются только в **новом** Codespace, который остановился в Recovery Mode. Если в нём уже есть ключи в `~/.ploom-enrollment`, сначала сохраните их по инструкции следующего раздела.

1. После слияния исправления в `main` откройте **Terminal → New Terminal** в новом Codespace. В корне проекта выполните `git status --short --branch`. Для чистой ветки `main` выполните `git pull --ff-only origin main`. При другой ветке или локальных изменениях создайте новый Codespace на обновлённой `main`, сохранив текущий.
2. В палитре команд (**F1**) выберите **Codespaces: Rebuild Container** и подтвердите пересборку. После открытия терминала выполните `whoami`, затем `cargo-tauri --version`. Ожидаются `vscode` и `tauri-cli 2.12.6`. При повторном Recovery Mode сохраните журнал **Codespaces: View Creation Log**.
3. В Explorer загрузите скачанный `partial.age` в папку `.ploom-release` в корне проекта. Выполните `python3 scripts/rescue-enrollment.py import`, затем `python3 scripts/codespaces-release.py`. Сохраните старый Codespace до проверки полной внешней резервной копии.

## Если предыдущий запуск остановился с кодом 127

Сохраните старый Codespace до проверки внешней резервной копии. После включения исправления в `main` выполните следующие действия в браузере.

1. В терминале **старого** Codespace откройте корень Ploom и выполните блок ниже. Утилита перенесёт имеющиеся ключи из `~/.ploom-enrollment` в зашифрованный архив и проверит его расшифровкой. Запишите пароль в менеджер паролей. В Explorer выберите **.ploom-release → partial.age → Download**. Если каталог с ключами отсутствует, переходите к обычной настройке ниже.
   ```bash
   git fetch origin main &&
   git show FETCH_HEAD:scripts/rescue-enrollment.py > /tmp/ploom-rescue.py &&
   python3 /tmp/ploom-rescue.py export
   ```
2. Создайте **новый** Codespace по шагу 2 ниже. Через Explorer создайте в корне проекта папку **.ploom-release**, выберите **Upload** и загрузите **partial.age**. В терминале выполните `python3 scripts/rescue-enrollment.py import`. Введите пароль архива. Утилита откажется перезаписывать существующий набор.
3. Выполните `python3 scripts/codespaces-release.py` и продолжите с шага 3 ниже. Мастер использует восстановленный Android-ключ. Удалять старый Codespace можно после проверки полной внешней копии **ploom-release.gpg**.

## Доступ и стоимость

Нужны личный аккаунт владельца itzme-work, браузер и возможность скачать и сохранить файл. Локальные Git, GitHub CLI, JDK, Android SDK, Node.js, Rust, WSL и Tailscale не нужны. Мастер использует терминал VS Code **в браузере**. Инструменты работают в облачном контейнере.

GitHub Free для личных аккаунтов включает месячную квоту Codespaces (120 core-hours, то есть до 60 часов на двухъядерной машине, и 15 GB-month хранения). Перед началом проверьте **Settings → Billing and licensing → Usage / Budgets and alerts**. Используйте минимальную машину и бесплатный остаток. Удалите Codespace после настройки. Без платёжного метода использование заканчивается при исчерпании включённой квоты. Стандартные GitHub-hosted runners бесплатны для публичных репозиториев при стандартных условиях GitHub Actions. Запрещающие политики аккаунта, отсутствие квоты или отключённые Actions могут препятствовать запуску. [Условия Codespaces](https://docs.github.com/en/billing/concepts/product-billing/github-codespaces) · [Биллинг Actions](https://docs.github.com/en/billing/concepts/product-billing/github-actions)

## Один раз

1. Проверьте изменения и включите их в основную ветку официального **itzme-work/Ploom**. Код из этой ветки получит доступ к подписям. Закройте запись в основную ветку для недоверенных участников.
2. Откройте **Code → Codespaces → … → New with options**, выберите основную ветку, конфигурацию **Ploom Release — Debian 12**, личный аккаунт и двухъядерную машину. Нажмите **Create codespace** и откройте его в браузере. Не включайте сторонние расширения, dotfiles или общий доступ к терминалу. Откройте **Terminal → New Terminal** и введите:
   ```bash
   python3 scripts/codespaces-release.py
   ```
3. Мастер проверит GitHub-аккаунт, origin, ветку, SHA и чистоту рабочей копии. Он создаст Environment **ploom-release**, если хватает прав. **Если GitHub вернул 403**, создайте Environment через **Settings → Environments → New environment → ploom-release**. Если токен Codespaces всё ещё ограничен, создайте короткоживущий fine-grained token через **Settings аккаунта → Developer settings → Personal access tokens → Fine-grained tokens**. Выберите только **itzme-work/Ploom**, **Contents: read**, **Actions: read** и **Environments: read and write**. Передайте его в *скрытый* запрос терминала следующим блоком и отзовите по окончании. Значение вводится после появления запроса. Не вставляйте токен в текст команды, файлы или переписку.
   ```bash
   ( read -rsp 'GitHub token: ' GH_TOKEN && echo && export GH_TOKEN && python3 scripts/codespaces-release.py )
   ```
4. Подтвердите имя репозитория. Сохраните в менеджере **отдельный стойкий пароль резервной копии** и пароль ключа Tauri. Мастер создаст Android PKCS#12 и Tauri keypair; пароль контейнера Android генерируется автоматически. В Explorer раскройте **.ploom-release** (при необходимости Refresh). Нажмите правой кнопкой **ploom-release.gpg → Download**. Сохраните копию на защищённом носителе. На своём устройстве переименуйте скачанный файл в **restore.gpg**, затем **Explorer → .ploom-release → Upload** и выберите этот файл. Вернитесь в терминал и нажмите Enter. Мастер расшифрует возвращённую копию, проверит Android-сертификат, подпишет случайный образец и проверит подпись публичным ключом Tauri. Только затем он отправит недостающие значения в GitHub Environment Secrets через GitHub CLI. В архиве есть оба закрытых ключа и их пароли; пароль самого архива храните отдельно.
5. В **Settings → Environments → ploom-release** ограничьте deployment branches основной веткой. При необходимости добавьте required reviewers. Убедитесь, что видны четыре имени RELEASE_ANDROID_PASSWORD, RELEASE_ANDROID_P12_BASE64, RELEASE_TAURI_PASSWORD, RELEASE_TAURI_KEY и две variables ANDROID_CERT_SHA256 и UPDATER_PUBLIC_KEY. Затем на **github.com/codespaces → … → Delete** удалите свою временную машину, если внешняя копия проверена. Удаление файлов штатными средствами не гарантирует физическое стирание блоков в облаке.

**Повтор / восстановление.** В новом чистом Codespace создайте через Explorer каталог .ploom-release и загрузите в него свою копию как restore.gpg до запуска мастера. При уже существующих привязках мастер требует исходную копию и сверяет идентификаторы. Присутствующие секреты пропускаются. GitHub скрывает их значения, поэтому окончательная проверка соответствия загруженным ключам — успешный Build only. Если доступен только архив от Windows-мастера в другом формате, используйте исходный Windows-процесс; новая генерация поверх привязок заблокирована.

**Если настройка прервалась**, сохраните тот же Codespace. Временный каталог ~/.ploom-enrollment принадлежит владельцу и содержит чувствительные данные. Когда ploom-release.gpg уже создан, скачайте и верните его как restore.gpg, затем повторите команду. При прерывании генерации повторите команду в том же Codespace и используйте исходный пароль Tauri. Не удаляйте единственную копию ключей. Если сбой произошёл при восстановлении в новом Codespace, сначала убедитесь, что внешний архив и его пароль доступны. После этого можно удалить временную машину и повторить восстановление в чистой.

## Для каждой версии

Откройте **Actions → Publish Ploom → Run workflow**, выберите основную ветку и введите версию в формате X.Y.Z или X.Y.Z-beta.N.

| Цель | Что выбрать | Результат |
|---|---|---|
| Проверить подписанные пакеты | Оставить **Build only**, нажать **Run workflow** | Сборка, проверка обеих подписей и метаданных; в Summary → Artifacts появится verified-release на три дня. Задача publish пропускается. |
| Выпустить версию | Выбрать **Publish**, отдельно поставить флажок подтверждения и нажать **Run workflow** | После проверки пакетов отдельная задача с правом записи создаёт черновик тега, загружает файлы и публикует Release. При настроенных reviewers потребуется их одобрение. |

Build only не создаёт тег или Release. **Артефакты Actions в публичном репозитории доступны пользователям с правом чтения**. Не используйте этот режим для конфиденциальных сборок. Для закрытых испытаний доступен [приватный сценарий](update-rehearsal.md).

## Доверие и приёмка

Codespaces — облачная машина под управлением GitHub. Во время генерации и расшифровки приватный материал доступен процессам вашего пользователя и потенциально администратору среды, вредоносному расширению или модифицированному образу. Используйте чистую машину, проверенный коммит и минимальные разрешения, проводите настройку в одном сеансе за раз. Не включайте shell tracing, отладочные логи gh или трансляцию экрана. Для требований к локальной генерации доступен [мастер Windows](updates.md). Выпуск через Actions в обоих случаях предполагает доверие к защищённому release workflow и его runner.

Перед объявлением стабильной версии пройдите переход между двумя подписанными версиями Windows и физического Android. Зафиксируйте версию, язык, стиль и акцент до обновления и после перезапуска, отмену системного диалога Android и отказ при подмене подписи. [Чек-лист устройств](device-validation.md)
