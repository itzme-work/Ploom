# Проверка на Redmi Pad SE с Android 15

В исходном APK 0.1.0 зарегистрированы два компонента с одним классом AndroidX FileProvider и разными authorities. Android может повторно использовать уже загруженный компонент с другими правилами доступа к файлам. Код Android 15 индексирует локальные провайдеры по паре «пакет, класс». У второй записи с тем же классом используется прежний экземпляр. [ActivityThread.installProvider в AOSP](https://github.com/aosp-mirror/platform_frameworks_base/blob/android-15.0.0_r1/core/java/android/app/ActivityThread.java#L8314). В исправлении у APK собственный класс провайдера и узкий каталог. Перед запуском установщика Ploom открывает выданный content URI и сверяет длину. Файл сохраняется в закрытом каталоге после запуска установщика. Очистка при следующем обновлении касается файлов старше суток. Для подтверждения причины конкретной ошибки HyperOS нужны результат проверки на планшете или системный журнал момента отказа.

1. После слияния PR владельцем откройте **Actions → Publish Ploom → Run workflow → main**. Введите версию **0.1.2**, выберите **Build hotfix pair** и нажмите **Run workflow**. Этот режим собирает оба фиксированных номера и пропускает публикацию. Используются прежние ключи из ploom-release. Дождитесь проверки обоих пакетов и скачайте архивы **verified-0.1.2** и **verified-0.1.3** во вкладке Artifacts.
2. Распакуйте архив 0.1.2 штатными средствами и откройте **Ploom-arm64.apk** поверх установленного Ploom. Проверьте **0.1.2**, выберите канал **Beta**, запомните или сфотографируйте настройки. Проверьте облачко на рабочем столе и при запуске приложения.
3. Только после отдельного решения о публичном тесте владелец может открыть **Releases → Draft a new release**, выбрать новый тег **v0.1.3** на коммите подписанной сборки, отметить **Set as a pre-release** и загрузить все четыре файла из **verified-0.1.3** без переименования. Перед публикацией проверьте тег, файлы и пометку предварительного релиза. Черновик и ZIP из Actions клиенту недоступны.
4. В 0.1.2 нажмите **Проверить обновления → Обновить Ploom**. Попробуйте отменить загрузку и повторить. При первом запросе разрешите установку из Ploom. В системном окне сначала нажмите **Отмена**, затем повторите и подтвердите обновление. После запуска проверьте номер 0.1.3 и все настройки. При ошибке запишите её текст и этап. Кнопка **Скачать APK через браузер** открывает официальный файл той же версии. Удаление приложения для повторной попытки не требуется.

Ручную проверку Windows в этом цикле выполнят позднее. CI извлекает иконки NSIS и EXE, а защищённая сборка пары проверяет установку на месте и настройки в WebView2.
