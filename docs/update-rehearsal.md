# Репетиция 0.1.0 → 0.1.1-test

Используйте чистый профиль Windows и выделенный Android без существующей установки Ploom. Обе версии используют work.itzme.ploom и одно имя продукта. Конфликт с подписью ранее установленного клиента требует другого тестового устройства или профиля. Удаление существующего приложения может уничтожить данные.

## Однократная подготовка владельцем

1. В доверенной локальной копии выполните npm ci в apps/client, затем из корня bash scripts/setup-signing.sh --test. Нужны Bash и JDK. Мастер создаёт отдельный каталог ploom-rehearsal внутри XDG_DATA_HOME (обычно ~/.local/share) и отказывается перезаписывать его. Введите стойкие пароли интерактивно. Сохраните пароли в менеджере и зашифрованную резервную копию каталога отдельно. Для официального релиза используется другой профиль ключей.
2. В GitHub создайте защищённое environment ploom-rehearsal с обязательным утверждением владельца и доступом только для native-completion. Задайте variables STAGING_HOST (DNS-имя собственного тестового HTTPS-хоста) и TEST_UPDATER_PUBLIC_KEY (содержимое updater.key.pub). Секреты TEST_TAURI_KEY и TEST_TAURI_PASSWORD содержат закрытый ключ Tauri и его пароль. TEST_ANDROID_P12_BASE64 содержит Base64 от android.p12, TEST_ANDROID_PASSWORD — пароль контейнера. Вводите значения через защищённую форму или stdin команды gh secret set. Например, gh secret set TEST_TAURI_KEY --env ploom-rehearsal < /путь/updater.key и base64 < /путь/android.p12 | gh secret set TEST_ANDROID_P12_BASE64 --env ploom-rehearsal. Включите историю GitHub Environment и проверьте права перед одобрением запуска.
3. После появления определения Signed test packages в ветке по умолчанию вручную запустите его с ref native-completion. GitHub требует регистрации workflow_dispatch в ветке по умолчанию. Перед одобрением проверьте SHA и шаги. Матрица собирает обе версии на обеих ОС с одними и теми же тестовыми ключами, публикует только Actions artifacts. Артефакт Windows содержит установщик и отделённую подпись Tauri. Эта подпись служит для updater. Android проверяется apksigner. Сохраните номера запусков, SHA, отпечатки публичных ключей и артефакты для воспроизведения.

## Изолированная раздача

Ограничьте доступ к тестовому хосту сетью лаборатории. Нужен HTTPS с сертификатом, которому доверяют обе ОС. В репетиционных бинарниках хост фиксируется при сборке. Рабочие исходники продолжают обращаться к официальному GitHub. Используйте обычные ответы 200 без перенаправлений и разрешите CORS для запроса releases.json из WebView (тестовый статический файл допускает Access-Control-Allow-Origin: * без credentials).

Разложите на тестовом хосте три файла новой версии под /itzme-work/Ploom/releases/download/v0.1.1-test/ — Ploom.exe, Ploom.exe.sig и Ploom-arm64.apk. По адресу /releases.json разместите следующий JSON. Параметры запроса первой страницы не меняют ответ.

```json
[{"draft":false,"prerelease":true,"tag_name":"v0.1.1-test","body":"Проверка сохранения настроек"}]
```

По адресу /itzme-work/Ploom/releases/download/beta-feed/latest.json разместите JSON ниже, подставив hostname и точное содержимое файла Ploom.exe.sig. На Stable тестовая версия должна оставаться скрытой.

```json
{"version":"0.1.1-test","notes":"Проверка обновления","platforms":{"windows-x86_64":{"url":"https://HOST/itzme-work/Ploom/releases/download/v0.1.1-test/Ploom.exe","signature":"СОДЕРЖИМОЕ_SIG"}}}
```

## Протокол приёмки на каждой ОС

1. Установите тестовую 0.1.0, зафиксируйте версию, выберите Beta, ASCII, русский язык и янтарный акцент. Перезапустите приложение и проверьте значения. Сделайте снимок тестовой ВМ или резервную копию профиля до обновления.
2. Сначала проверьте отказ. В отдельной попытке подмените копию Windows-подписи или измените подписанный APK на стенде. Запустите обновление. Установка должна прерваться, прежняя версия и настройки должны открываться. Верните оригиналы. Аналогично проверьте обрыв сети.
3. На Android проверьте apksigner verify --verbose --print-certs для обоих APK. Отпечатки должны совпасть. Через apkanalyzer manifest application-id и manifest version-code сравните идентификатор и возрастающие коды (100 → 101). Нажмите обновление, отмените системный диалог и убедитесь, что по-прежнему открывается 0.1.0. Повторите и подтвердите установку в Android. При первом запросе разрешите установку из Ploom только на тестовом устройстве и повторите действие.
4. На Windows нажмите обновление. После перезапуска проверьте версию в Ploom и в свойствах установленного продукта. На Android откройте приложение с ярлыка. На обеих платформах версия должна стать 0.1.1-test, настройки и канал должны сохраниться. Наличие только загруженного файла или открытого системного диалога успехом не считается.
5. После успешного перехода верните в тестовые метаданные 0.1.0. Повторная проверка не должна предлагать понижение. Зафиксируйте статус, версии до и после, отпечатки, настройки и результат каждой попытки. Будущие подписки проверить в этой версии невозможно.

При сбое прекратите раздачу проблемного пакета, сохраните журнал и текущие данные приложения. Для повторения верните снимок изолированного профиля или ВМ. В рабочей среде путь восстановления — исправленная сборка с более высокой версией и той же доверенной подписью. Стабильный выпуск требует отдельного решения владельца после успешного теста обеих платформ.
