# Проверка установленного Ploom

Запишите модель, версию ОС, ABI, версию WebView/WebView2, SHA сборки и время. Для Android нужен ARM64-телефон. Для Windows нужен x64-компьютер с WebView2. На тестовом профиле выполните одинаковые шаги на обеих платформах.

- [ ] Запустите с ярлыка в авиарежиме или без сети. Видны заголовок, кнопка и статус «Отключено». Повторите холодный запуск. На Android сверните и восстановите приложение.
- [ ] Выберите по очереди Material, Liquid Glass, Fluent и ASCII. Проверьте светлый и тёмный режимы. На Windows измените размер окна и масштаб экрана, на Android поверните экран и откройте клавиатуру в форме. Текст, кнопки и нижняя навигация должны оставаться доступны.
- [ ] Выберите ASCII, янтарный акцент и русский язык. Полностью закройте приложение и снова запустите с ярлыка. Проверьте все три значения, затем переключитесь на English.
- [ ] Нажмите «Подключиться». Должно появиться сообщение о будущей функции, статус остаётся отключённым. ОС не показывает запрос VPN или активный туннель.
- [ ] С выключенной автопроверкой запишите домены соединений процесса при запуске и переходе по четырём экранам. Используйте системную трассировку процесса или сетевой журнал WebView. Отметьте отдельно системный трафик WebView и приложения. Без явного действия клиент не должен обращаться к API релизов или по адресу, введённому в форме.
- [ ] При отключённой сети нажмите «Проверить обновления». Должна появиться ошибка. Включите сеть и повторите. Сохраните фактический результат, включая случай пустого списка релизов.

Для каждого сбоя сохраните шаг, ожидаемый и фактический результат, снимок экрана и обезличенный журнал. Используйте только синтетические значения для подписок.

## Проверка тестовых сборок 0.3.0 с ядром

1. Возьмите тестовый комплект из workflow **Android libbox ARM64**. Запишите SHA, режим и версию ОС. Выберите собственный тестовый сервер. Для LAN подтвердите ровно тот IP и порт, которые указаны у вашего сервера.
2. На Android отклоните запрос VPN при первой попытке. Повторите подключение и подтвердите системный диалог. Проверьте системное уведомление, прохождение известного запроса на стороне тестового провайдера, отключение из уведомления и исчезновение VPN из настроек Android.
3. Повторите запрос после сворачивания, блокировки экрана и перехода между Wi-Fi и мобильной сетью. Отметьте, восстанавливается ли связь и как ведут себя счётчики; зафиксируйте настройки энергосбережения HyperOS. Для проверки HTTPS кнопкой Ploom потребуется согласие на запрос к connectivitycheck.gstatic.com через провайдера.
4. При открытии сканера отдельно проверьте отказ в доступе к камере, автофокус, фонарик и QR в горизонтальной ориентации. До подтверждения импортированной конфигурации сеть не должна меняться.
5. На Windows запишите текущий системный прокси. В режиме Local Proxy проверьте реальный запрос прикладным клиентом. В System Proxy проверьте приложение, использующее настройки Windows, затем отключение и аварийное завершение. Сравните настройки Windows с первоначальными. Проверку полноценного пользовательского Windows TUN выполняют после интеграции безопасного запроса полномочий.
6. Для проверки миграции на физическом Android нужен APK с подписью установленного экземпляра. Debug APK использует другой ключ. Сохраните резервную копию и дождитесь пары совместимо подписанных сборок для установки поверх существующей библиотеки.
