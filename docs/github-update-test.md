# Проверка обновления 0.1.0 → 0.1.1

Обе версии собирает **Publish Ploom → Build only** с существующими ключами. До разрешения владельца файлы доступны в Actions. Установленный клиент читает общедоступный список GitHub Releases без авторизации. Черновики и ZIP-архивы Actions недоступны его механизму обновлений. Канал Beta видит публичный предварительный релиз с тегом **v0.1.1** и номером пакета **0.1.1**. Stable пропускает его. Предварительный релиз виден любому посетителю GitHub и всем клиентам Beta. Для этой проверки не требуется публиковать 0.1.0.

## До публикации

1. Войдите в GitHub и скачайте **verified-release** из [сборки 0.1.0](https://github.com/itzme-work/Ploom/actions/runs/45405812136). Распакуйте ZIP средствами ОС. Сохраните также [сборку 0.1.1](https://github.com/itzme-work/Ploom/actions/runs/45408186512). Исходные артефакты хранятся три дня. Для повторения позже соберите обе версии через **Build only** и введите новые номера запусков в **Check signed update pair**.
2. На тестовом Windows x64 установите **Ploom.exe**, на физическом Android ARM64 версии 9 или новее откройте **Ploom-arm64.apk**. Используйте чистый тестовый профиль, если на устройстве уже есть debug-сборка или более новая версия. Откройте настройки и убедитесь, что отображается **0.1.0**.
3. Выберите **Beta**, оставьте автопроверку выключенной. Измените язык, стиль, светлый/тёмный режим, акцент, масштаб, шрифт, прозрачность, эффекты, анимации и звук. Сделайте снимок всех настроек на каждом устройстве. Закройте и снова откройте приложение.

## Когда владелец разрешит публичный тест

4. После слияния PR откройте **Actions → Check signed update pair → Run workflow** на ветке **main**. Проверьте номера двух запусков. Только для публичного теста поставьте флажок **Publish the verified 0.1.1 files publicly as a GitHub prerelease**. Подтвердите запуск и, если GitHub запросит, deployment. Без флажка выполняются проверки пакетов. После успешной публикации проверьте пометку **Pre-release** и четыре файла в теге **v0.1.1**. Если тег уже существует, workflow остановится. Не заменяйте его содержимое.
5. В Ploom 0.1.0 на каждом устройстве нажмите **Проверить обновления → Обновить Ploom**. Подтвердите установку поверх текущей версии. На Android при запросе разрешите установку из Ploom и повторите действие. Если Windows показывает предупреждение SmartScreen, действуйте согласно политике устройства. При ошибке подписи остановите тест и запишите текст ошибки.
6. Откройте приложение с прежнего ярлыка и проверьте **0.1.1**, затем сравните все настройки со снимком. Перезапустите приложение и проверьте ещё раз. На канале Beta повторная проверка при отсутствии более новых релизов должна показать актуальную версию. Зафиксируйте платформу, версию ОС, результат установки и различия настроек отдельно для Windows и Android.

## Какие доказательства даёт автоматизация

Проверка пары сравнивает идентификатор и сертификаты двух APK, versionCode (100099 → 100199), метаданные Windows и результаты проверки чужих подписей на одноразовых образцах. На Windows runner NSIS последовательно устанавливает обе версии в одну папку, а тест читает настройки установленного приложения через WebView2 и проверяет поведение при ответе со старой версией. Шаги 5–6 проверяют реальную загрузку с GitHub, системное подтверждение и повторный запуск на устройствах. Неверно подписанные файлы для этих проверок в Releases не загружаются.
